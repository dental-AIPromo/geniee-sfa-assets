# geniee-sfa-assets GitHub Pages構築計画

## 対象

- Repository: `dental-AIPromo/geniee-sfa-assets`
- Default Branch: `main`
- 想定公開URL: <https://dental-aipromo.github.io/geniee-sfa-assets/>

## 目的

GENIEE SFAなどから参照する公開可能な画像・静的アセットを、GitHub Pagesで公開する。`main` へのPushを起点にGitHub Actionsで自動Deployし、利用者はGitHub Desktop等で画像の追加、Commit、Pushを行えばよい運用とする。

## 実装方針

1. Pages用Workflowを `.github/workflows/deploy-pages.yml` に配置する。
2. Workflowは `main` へのPushおよび手動実行をトリガーとする。
3. GitHub公式Actionsの `checkout`、`configure-pages`、`upload-pages-artifact`、`deploy-pages` を使用する。
4. `contents: read`、`pages: write`、`id-token: write` の最小権限を設定する。
5. Deployment Environmentを `github-pages` とする。
6. Repository直下の `index.html` と `images/` だけをWorkflow内の一時ディレクトリへコピーし、そのディレクトリをPages artifactとしてアップロードする。READMEやWorkflowなどの管理用ファイルは公開artifactに含めない。
7. `index.html` はRepository名とPages稼働状態だけを示す最小ページとする。
8. `README.md` に目的、公開URL、画像追加方法、URL規則、自動Deploy、公開禁止情報を記載する。
9. `images/.gitkeep` を置き、画像配置先を明示する。

## 影響範囲

- Repository内: Workflow、トップページ、README、画像配置ディレクトリ、Git除外設定
- GitHub設定: Pagesの公開元を `GitHub Actions` に設定する必要がある。RepositoryコードからはSettings変更を行わない。
- 公開情報: `main` にPushしたファイルはインターネット公開される。

## 検証計画

1. 旧Organization名の記述が成果物に残っていないことを検索する。
2. WorkflowのYAML構文を検証する。
3. `permissions`、`github-pages` Environment、`main` Pushトリガー、4つの公式Actionsを確認する。
4. Workflowが`main`以外ではDeployしないことを確認する。
5. Pages artifactが`index.html`と`images/`だけで構成されることを確認する。
6. 必須ファイルとディレクトリ構成を確認する。
7. GitHub側でPush後にActionsとPagesのDeployが成功した後、トップページと画像URLを確認する。
